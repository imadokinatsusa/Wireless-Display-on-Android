# 11: 反向控制 —— 事件回传与无障碍注入

**What to build:** 接收端采集触摸手势（点按、长按、滑动、双指缩放）与外接键盘/鼠标输入，回传给发送端，由发送端通过 `AccessibilityService` 注入真实系统输入。仅在已配对且加密的会话中可用。用户价值：在平板上直接操作手机，不用走过去。
**Blocked by:** 10（配对、密钥协商与全链路加密）
**Status:** ready-for-agent

- [ ] `InputEvent` 模型与序列化：触摸（动作类型、归一化坐标、多指、时间戳）、按键、文本输入
- [ ] 接收端手势采集：把屏幕手势映射为归一化坐标事件，含多指与滑动；外接鼠标（含滚轮）与键盘可达
- [ ] 控制通道传输：走可靠通道，事件有序且延迟可控（目标往返 < 50ms）
- [ ] 发送端 `InputInjector`：基于 `AccessibilityService` 的 `dispatchGesture` 与按键/文本注入
- [ ] 授权引导：发送端清晰说明为什么需要无障碍权限、如何开启、如何在系统设置里找到；未授权时反向控制入口不可用且说明原因
- [ ] 隐私控制：发送端有一键撤销开关，开启期间界面上持续显示"正在被远程控制"的状态
- [ ] 安全约束：只有已配对且加密的会话能发控制事件；未配对/未加密时控制通道关闭
- [ ] 无障碍服务被系统回收/被用户关闭时，接收端能感知并提示（降级为只看不控），而不是默默失效
- [ ] 手工验收：在接收端完成点按、长按、滑动、双指缩放、文字输入、按键操作，发送端行为正确；撤销后立刻失效
- [ ] 坐标逆变换：接收端视图坐标经 `ViewTransform`（缩放/平移）还原为全屏归一化源屏坐标，若处于 ROI 模式再经 ROI 映射还原；缩放、平移、贴边、极端倍率下点按位置都与预期一致（纯函数 + 往返一致性测试）
- [ ] 纯逻辑有单测：事件序列化往返、归一化坐标变换、未授权状态下的拒绝路径
