# 08: 系统音频内录与音画同步

**What to build:** 发送端用 `AudioPlaybackCapture` 内录系统声音并编码传输，接收端播放，且音频与画面偏差控制在 50ms 内（音频为主时钟，视频向音频对齐）。用户价值：看视频有声音且不出戏。
**Blocked by:** 06（真机端到端屏幕镜像打通）
**Status:** ready-for-agent

- [ ] `AudioSource` 生产实现：`AudioPlaybackCapture` 采集（Android 10+，需 MediaProjection 授权），采样率/声道与协商结果一致
- [ ] 音频编码与传输：走媒体通道，与视频共用会话与时间戳体系
- [ ] 接收端 `AudioSink`：低延迟播放路径，缓冲可配置且可观测
- [ ] `MediaClock` 以音频为主时钟，视频向音频对齐；音画偏差有实测指标（目标 < 50ms）
- [ ] 发送端可单独关闭音频（只投画面），UI 状态明确
- [ ] 被投屏应用声明禁止捕获时优雅降级为"仅画面"，并在 UI 与状态里说明原因，不静默无声
- [ ] 纯逻辑有单测：音频包重组、时间戳对齐逻辑、偏差计算（用可控时钟）
- [ ] instrumentation 冒烟：采集能拿到音频缓冲并编码出首个音频帧
- [ ] 手工验收清单：播放音乐/视频时听感无回声、无爆音，音画偏差在可接受范围；投屏期间接打电话不崩溃
