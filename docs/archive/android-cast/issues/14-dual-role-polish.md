# 14: 双角色体验收尾与权限引导

**What to build:** 把整条链路打磨成一个"不用看说明书就能用"的应用：单 APK 内角色切换、默认角色按设备形态猜测、所有权限集中引导、会话中状态与错误恢复体验统一、一推多的架构余地确认没被写死。用户价值：第一次打开就能自己搞定从配对到投屏的全流程。
**Blocked by:** 11（反向控制 —— 事件回传与无障碍注入）、12（自适应码率与拥塞应对）
**Status:** ready-for-agent

- [ ] 角色切换干净：同一台设备可先当发送端再当接收端，切换时采集/渲染/注入/前台服务资源全部正确释放，无泄漏无残留通知
- [ ] 默认角色按设备形态猜测（手机偏发送、平板/电视偏接收），用户可改且偏好被记住
- [ ] 权限集中引导：屏幕录制、通知、无障碍、常亮等权限有一处统一入口，说明每条为什么需要，未授权时对应功能不可用且有解释
- [ ] 会话界面统一：连接中/投屏中/重连中/已断开四种状态与对应可执行动作清晰，不出现无提示的死状态
- [ ] 会话统计面板统一展示：码率、帧率、端到端延迟、丢包率、当前档位、控制开关状态
- [ ] 观看缩放体验收尾：进入/退出放大与 ROI 模式切换平滑无黑屏，状态面板显示当前倍率与是否处于 ROI 模式，ROI 回落时给出可见原因
- [ ] 断线重连体验：网络恢复后自动重连（已配对设备免 PIN），重连过程有可见进度
- [ ] 错误文案面向用户：每种失败都有"发生了什么 + 可以怎么办"，不暴露异常栈
- [ ] 架构余地复查：`SessionId` 与通道结构未被写死为单会话假设，代码里为一推多/多收一留有清晰扩展点（不实现功能，只确认不阻塞）
- [ ] 手工验收：给一个没用过的人一台手机 + 一台平板，不口头指导完成"配对 → 投屏 → 反向控制 → 录制 → 断开 → 重连"全流程
- [ ] 端到端回归清单过一遍：切片 06/07/08/10/11 的验收项在最终形态下仍全部成立
