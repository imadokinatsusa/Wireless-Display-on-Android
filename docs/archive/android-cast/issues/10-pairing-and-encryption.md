# 10: 配对、密钥协商与全链路加密

**What to build:** 首次连接做 PIN 或二维码配对，用临时 ECDH + PIN 确认抵抗中间人，之后控制面与媒体面全部 AES-128-GCM 加密，配对过的设备免 PIN 重连。用户价值：同一 Wi-Fi 下的旁人抓包看不到我的屏幕，也不能冒充对端。
**Blocked by:** 09（设备发现与手动连接入口）、03（会话握手与能力协商）
**Status:** ready-for-agent

- [ ] 首次配对流程：一端展示 6 位 PIN，另一端输入并确认；或接收端展示二维码，发送端扫码完成（含一次性公钥指纹）
- [ ] 临时 ECDH（P-256）密钥协商 + PIN/二维码秘密确认，中间人尝试会导致配对失败并有可读提示
- [ ] `PairingGrant` 派生与持久化：长期公钥、设备 ID、信任关系；支持在 UI 上删除配对
- [ ] 全链路加密：控制面与媒体面统一 AES-128-GCM，包序号参与 nonce，重放包被拒绝
- [ ] 免 PIN 重连（`TrustedReconnect`）：已配对设备直接建立加密会话，UI 上能区分"已配对"与"陌生设备"
- [ ] 陌生设备连接请求必须经过配对，不能跳过；拒绝后对端得到明确原因
- [ ] 加密与配对纯逻辑有单测：加解密往返、nonce 重放拒绝、PIN 错误失败、密钥不匹配失败、配对持久化与重连信任判断
- [ ] 手工验收：用抓包工具确认媒体与控制流量均不可读；配对失败路径（输错 PIN、伪造指纹）均被拒绝
- [ ] 加密开启后性能可接受：1080p@60 下加密开销不使端到端延迟超出预算（有实测数据）
