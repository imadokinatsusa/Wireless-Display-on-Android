# 07: UDP 媒体通道、抖动缓冲与关键帧恢复

**What to build:** 把视频包从 TCP 迁移到 UDP，配上包序号检测、关键帧请求与抖动缓冲，让画面在网络抖动时**优先保延迟**（宁可短暂丢帧/糊化）而不是越看越延迟。用户价值：20 分钟投屏后延迟不累积，玩游戏也能操作。
**Blocked by:** 06（真机端到端屏幕镜像打通）
**Status:** ready-for-agent

- [ ] `MediaChannel` 的 UDP 实现落地：媒体包走 UDP，控制面仍走 TCP 可靠通道，握手阶段协商端口
- [ ] 包序号检测：重复包、乱序包、丢失包被正确识别；整形帧缺包时丢弃该帧而非等待
- [ ] `KeyframeRequest` 控制消息：接收端请求后发送端立刻编一个 I 帧，恢复时间可量化（目标 < 300ms）
- [ ] `JitterBuffer` 落地：按时间戳重排，目标延迟可配置且能自适应网络抖动
- [ ] 延迟策略可验证：人为注入丢包/抖动/限速（本地网络整形或测试用假通道），画面不出现累积延迟增长
- [ ] 对照切片 06 记录的 TCP 基线，给出 UDP 化的延迟与卡顿改善数据
- [ ] 纯逻辑部分有单测：乱序重组、丢包丢弃、重复包去重、抖动缓冲的目标延迟推进（用可控时钟）
- [ ] UDP 端口不可达/被防火墙拦截时自动回退到 TCP 媒体通道并告知用户
- [ ] 手工验收：20 分钟连续投屏，端到端延迟不随时间增长（与切片 06 基线对比）
