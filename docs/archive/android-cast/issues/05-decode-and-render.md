# 05: 接收端硬件解码与渲染

**What to build:** 接收端把收到的真实 H.264 码流硬解并渲染到全屏 Surface，等到 I 帧再起播，能识别丢包造成的不完整帧并跳过而不是花屏等待。用户价值：平板/电视上第一次看到手机的真实屏幕，流畅且首帧不黑屏太久。
**Blocked by:** 03（会话握手与能力协商）
**Status:** ready-for-agent

- [ ] 接收端重组逻辑接到 `VideoSink`：把 `VideoPacket` 按帧重组成完整编码帧，缺包的帧被识别并丢弃（不喂给解码器）
- [ ] `MediaCodec` 异步模式解码，配置来自握手协商；`SurfaceView`/`TextureView` 渲染全屏
- [ ] 起播策略：先等 I 帧再喂解码器，首帧前显示"正在连接/等待画面"状态
- [ ] 解码器遇到不支持的码流时给出可读错误并触发重协商或重连，不静默卡住
- [ ] 渲染界面：全屏、保持屏幕常亮、可隐藏状态信息
- [ ] 视图变换交互：捏合缩放（倍率有上下限）、拖动平移（边界钳制、不留空白）、双击复位、适应/填充/原始比例三种显示模式
- [ ] `ViewTransform` 作为**可观察状态**对外暴露（供工单 15 推导 ROI、供工单 11 做触摸坐标逆变换），不藏在 View 内部
- [ ] 重组逻辑为纯逻辑并有单测：帧完整/缺首包/缺中间包/缺尾包/乱序到达/重复包六种情况的行为明确
- [ ] 结束与重连：对端断开、解码失败、Surface 销毁时不泄漏解码器与 Surface
- [ ] instrumentation 冒烟：向解码器喂入一段伪造的 I 帧能被接受且不崩溃
- [ ] 手工验收：用预置的 H.264 码流文件作为假 `VideoSource`，接收端能完整播放
