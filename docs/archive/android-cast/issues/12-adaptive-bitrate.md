# 12: 自适应码率与拥塞应对

**What to build:** 依据 `SessionStats`（丢包、延迟、可用带宽估计）动态调整目标码率、分辨率与帧率，让画面在弱网下自动降级、网络恢复后自动回升，而不是卡死或糊到底。用户价值：网络变差不手动折腾，体验自己会调整。
**Blocked by:** 07（UDP 媒体通道、抖动缓冲与关键帧恢复）、08（系统音频内录与音画同步）、15（ROI 高清放大 —— 码率预算必须理解 ROI 模式）
**Status:** ready-for-agent

- [ ] `BitratePolicy` 落地为纯逻辑：输入 `SessionStats` 序列，输出目标码率/分辨率/帧率决策
- [ ] 带宽与拥塞信号来源明确：接收端上报丢包率、抖动、解码耗时；发送端结合发送速率做估计
- [ ] 升降级策略：降级要快（避免卡顿持续）、回升要慢（避免震荡），有滞回与冷却时间
- [ ] 决策落地到编码器：运行时改变码率，分辨率/帧率变化按 `MediaCodec` 能力安全重启或重配置，不产生长时间黑屏
- [ ] 升降级对用户可见：界面上能看到当前档位与最近一次调整原因
- [ ] 纯逻辑单测覆盖：从良好网络恶化到极差再恢复的整条决策序列、边界值、频繁抖动下的震荡抑制（用可控时钟推进）
- [ ] ROI 取样下的码率预算：`SameResolution` 档不做分辨率级调整，但按"每源像素比特"理解取样变化，取样切换不产生码率震荡；`Native1to1` 档（冻结重配后）重新计算分辨率相关的预算
- [ ] 弱设备接收端场景：解码耗时高时触发降级（1080p → 720p），避免接收端成为瓶颈
- [ ] 手工验收：限速/注入丢包的网络环境下，画面自动降到可播放档位；恢复后自动回升且不反复横跳
