# 03: 会话握手与能力协商

**What to build:** 两端连上之后先"谈条件"再传数据：协商协议版本、交换能力（分辨率、帧率、编解码档位、是否支持音频/控制）、分配 `SessionId`、定下本次会话的媒体参数。用户价值：不再因为版本或设备能力不匹配而黑屏或花屏，而是得到明确提示或自动降级到双方都能跑的参数。
**Blocked by:** 02（真实局域网 TCP 可靠通道）
**Status:** ready-for-agent

- [ ] `Handshake` 消息定义与状态机：`Idle → Greeting → Negotiating → Established → Closing`，每个状态有超时
- [ ] 能力集交换与交集计算：分辨率/帧率/编码档位/音频支持/控制支持；无交集时返回可读的错误原因
- [ ] 协议版本不匹配时给出明确错误（"对端版本过旧/过新"），不是断连
- [ ] `SessionId` 生成与在后续所有消息中的携带（为一推多留余地，v1 单会话）
- [ ] 会话结束路径完整：任一端主动结束、超时结束、异常结束，对端都能收到明确原因并回到可重连状态
- [ ] 状态机单测覆盖全部路径：正常协商、版本不匹配、能力无交集、握手超时、协商中被动断开
- [ ] UI 上会话参数与状态可见（当前分辨率/帧率/编码档位）
- [ ] `Session` 的生命周期独立于 UI 组件（配置变更/旋转不打断会话）
