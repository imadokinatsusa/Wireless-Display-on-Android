# 06: 真机端到端屏幕镜像打通

**What to build:** 把切片 04 与 05 接起来，第一次实现完整的"手机真屏幕 → 平板显示"端到端投屏，并把可观测指标与延迟预算摊开在界面上。用户价值：产品的最小可用形态成立，能开始拿来用并按数据说话地优化。
**Blocked by:** 04（发送端真实采集与硬件编码）、05（接收端硬件解码与渲染）、02（真实局域网 TCP 可靠通道）
**Status:** ready-for-agent

- [ ] 发送端编码帧 → 包化 → TCP → 接收端重组 → 解码 → 渲染 全链路贯通，真机可见手机屏幕
- [ ] `SessionStats` 落地：端到端延迟、接收帧率、丢帧数、当前码率、丢包率，在接收端界面实时展示
- [ ] 延迟测量方法明确且可复现（发送端在帧数据里带采集时间戳，接收端在渲染回调算出端到端延迟）
- [ ] 界面按 `LatencyBudget` 展示各环节耗时（采集/编码/网络/缓冲/解码/显示），有测不准的环节要如实标注为估算
- [ ] 手工验收清单形成文档并逐条执行：1080p@60 端到端延迟、5 分钟稳定性、旋转屏幕、发送端息屏、接收端切后台、任一端拔网线/杀进程
- [ ] 明确记录 v1 已知短板：TCP 队头阻塞导致的延迟累积（切片 07 解决），并在验收里量化这个数字作为对照基线
- [ ] 首帧时间有指标且可接受（目标 < 2s，从点击开始到画面出现）
- [ ] 双方任一环节失败都有可读错误提示，不出现黑屏无提示的死状态
