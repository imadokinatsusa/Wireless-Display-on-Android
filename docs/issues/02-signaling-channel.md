# 02: 信令通道 —— 会话描述/候选交换 + 连接码校验（纯 JVM）

**What to build:** `:core:signal` 模块：定义信令消息模型与编解码、TCP 传输与超时重试、连接码校验。**不依赖 Android API**，因此能在本机 JVM 单测里跑通两个端点之间的完整交换。
**Blocked by:** 01
**Status:** ready-for-agent

媒体栈的信令是"未规定实现"的部分，只能自建；把它做成纯逻辑模块，是 M1 里唯一能本地验证的跨端逻辑。

- [ ] 消息模型：`Offer` / `Answer` / `Candidate` / `Bye`（会话描述与候选都是文本，原样搬运，不解析内容）
- [ ] 编解码：长度前缀 + UTF-8，畸形/超长/未知类型报文有明确拒绝语义
- [ ] 握手：首条消息携带连接码；不匹配 → 拒绝并给出可显示的原因
- [ ] 传输：监听/连接、消息收发、断开清理（一次会话一条连接，可重复建立）
- [ ] 超时与重试：等待对端的超时预算、失败原因（供诊断行显示）
- [ ] 单测（纯 JVM）：消息往返、畸形报文拒绝、连接码不匹配拒绝、超时、对端中途断开
- [ ] 集成测试：同进程两端口完成一次完整 offer/answer/candidate 交换
- [ ] 不引入任何 Android 依赖（`build.gradle.kts` 只有 `kotlin.jvm`）
