# 02: 信令通道 —— 会话描述/候选交换 + 连接码校验（纯 JVM）

**What to build:** `:core:signal` 模块：定义信令消息模型与编解码、TCP 传输与超时、连接码校验。**不依赖 Android API**，因此能在本机 JVM 单测里跑通两个端点之间的完整交换。
**Blocked by:** 01
**Status:** ✅ 完成（本地 20 个测试通过，2026-09-25）

媒体栈的信令是"未规定实现"的部分，只能自建；把它做成纯逻辑模块，是 M1 里唯一能本地验证的跨端逻辑。

## 交付物

| 文件 | 职责 |
| --- | --- |
| `SignalingMessage.kt` | 消息模型（`Hello` / `Offer` / `Answer` / `Candidate` / `Bye`）+ 文本编解码 |
| `SignalingFrame.kt` | 帧层：4 字节大端长度前缀 + 负载；长度越界一律判非法 |
| `SignalingChannel.kt` | `SignalingClient` / `SignalingServer` / `SignalingChannel` / `FrameIo` |

## 清单

- [x] 消息模型：会话描述与候选**原样搬运**，不解析 SDP 内容（解析与协商是媒体栈的事）
- [x] 编解码：首行类型 + 文本负载；未知类型 / 畸形候选 / 超长报文一律返回 null 而不是崩溃
- [x] 握手：首条必须是 `Hello`，连接码不匹配 → 关闭并给出可显示原因
- [x] 传输：监听（端口 0 由系统分配）、连接、收发、关闭；重复建立可用
- [x] 超时：握手读超时（默认 10s）+ accept 轮询超时；失败原因可直接显示在诊断行
- [x] 连接码不匹配只关这一条连接、继续等下一个（局域网上陌生连接是常态）
- [x] 单测：编解码 8 个 + 帧层 5 个 + 真实套接字 5 个 = **20 个**
- [x] 集成测试：localhost 真实 socket 完成握手 + 双向消息 + 对端关闭 + accept 超时
- [x] 不引入任何 Android 依赖（模块只有 `kotlin.jvm` 插件）

## 实现记录

- **不做本层重试**：连接失败/超时由上层（切片 03 的会话编排）决定是否重连；信令层只回答
  "这一次交换成不成"，避免两处超时逻辑打架。
- **文本而不是二进制**：SDP 本来就是文本，出问题可以直接打进诊断行看 —— 真机没有 adb，
  这是唯一的现场信息通道。
- **握手期间设 `soTimeout`、握手完成后清零**：否则对端连上却不说话会把接受方永久挂住；
  清零后转入正常的长连接等待。
