# 04: 音频端到端 —— 系统声音内录 → 音频轨 → 接收端播放

**What to build:** 把发送端正播放的声音（其它应用播放的媒体音）采集后，经媒体栈的音频轨发到接收端播放；验收要求音画偏差 ≤100ms。
**Blocked by:** 03；且规格待定项 A（音频如何注入媒体栈）必须先定稿
**Status:** ready-for-agent

**这是 M1 里唯一"库没有直接给"的能力**：libwebrtc 的默认音频设备模块自建 `AudioRecord`，
而系统内录需要 `AudioPlaybackCaptureConfiguration` 配置的 `AudioRecord`。路径由技术侦察定稿后写进本节。

- [ ] `RECORD_AUDIO` 运行时权限申请（与屏幕授权并列，失败原因可见）
- [ ] 内录配置：`AudioPlaybackCaptureConfiguration` + 匹配 `USAGE_MEDIA` / `USAGE_GAME` / `USAGE_UNKNOWN`
- [ ] 注入媒体栈：按定稿路径把 PCM 交给音频轨（候选：自定义音频设备模块 / 库已有的自定义音源 API）
- [ ] 接收端播放：由媒体栈渲染到系统音频输出，验证不需要额外自研播放器
- [ ] 静音说明：捕获不到的应用（未允许被捕获）在诊断行明确提示，不静默
- [ ] 不做回声处理的自研：AEC/NS/AGC 由库负责；只在真机上确认没有明显回声/爆音
- [ ] 诊断行补充：音频采样率、声道、A-V 偏差
- [ ] 手工验收：播放音乐/视频 → 接收端听到声音；说话/播放画面与声音基本同步
- [ ] 验收门槛：**音频不做通不发版**（见规格 §三）
