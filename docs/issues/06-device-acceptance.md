# 06: 真机验收 —— 延迟、A-V 偏差、10 分钟稳定性

**What to build:** 用两台真机跑验收：把规格 §三 的四项标准变成一组记录在案的实测数据；异常路径逐条走通；产出可交付的 Release APK。
**Blocked by:** 05
**Status:** ready-for-agent

- [ ] 连续投屏 10 分钟：记录延迟是否随时间增长（首分钟 vs 第十分钟）、有无崩溃/断连
- [ ] 端到端延迟：从诊断行记录（RTP 时戳 + 媒体栈统计推算），目标 ≤150ms
- [ ] 音画偏差：播放带明显节奏的音视频，记录诊断行的 A-V 偏差，目标 ≤100ms
- [ ] 分辨率与帧率：确认 1080p 级 @30fps（发送端屏幕真实尺寸）
- [ ] 异常路径逐条走通并记录现象：拒绝屏幕授权、拒绝录音权限、连接码填错、接收端中途退出、发送端切后台、Wi-Fi 切换
- [ ] 发热与耗电：连续 10 分钟后记录主观发热与电量下降（只记录，不设门槛）
- [ ] 出包：CI 成功 → Release 页给出 `app-debug.apk` 下载链接，手机上安装复验
- [ ] 结论写回本工单：达标 / 未达标项 + 原因与后续切片
